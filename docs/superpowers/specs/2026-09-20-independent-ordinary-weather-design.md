# AtmosScope 自有普通天气入口设计

日期：2026-09-20  
基线：`main` 的 v1.6.0 发布提交 `a0b9c72`  
阶段：v1.7 普通天气独立化，部署公开网址另行处理

## 目标和已确认的范围

用户希望普通天气不再依赖 ChatGPT Site 或登录，并能从 Web 页面、Android APK、Windows 安装程序打开。首阶段提供城市搜索、模式当前天气、未来 24 小时逐小时预报、未来 7 天预报，以及清楚的数据来源和缺测提示。已有专业图集的入口和数据逻辑保持可用。这个阶段不承诺复刻旧站点的完整界面：仓库没有旧普通天气页的源码，且其公开地址在当前环境无法读取。

“独立”指页面代码和导航不再指向 `chatgpt.site`；天气数据仍然需要联网取得。本阶段不宣称离线可用，也不在没有确定域名和数据授权方案时发布公网网址。

## 现状与选择

- `web/index.html` 是现有专业图集，已被 Android 打包到 assets、Windows 打包到 `Web`，不能把普通天气直接覆盖该入口。
- Android `MainActivity` 的“普通天气”加载 `chatgpt.site`，专业图集加载 `file:///android_asset/index.html`，并为后者开放了 file URL 跨源访问。
- Windows `MainWindow` 的“普通天气”加载同一外部网址，专业图集通过 `app.atmosscope.local` 虚拟主机访问本地 `index.html`。
- Android `strings.xml` 与 README 仍写着旧站点，测试仅检查有两个按钮而未保证普通天气真正本地运行。

比较过三条路径：继续包一层旧站点（改动少，但没有达到独立目标）；为 Android、Windows 分别开发原生普通天气（离线页面独立，却使维护和一致性成本增加）；在现有 `web/` 中增加一套共用静态页面并让三端加载同一份文件。选择第三条，因为两个安装程序已经携带 `web/`，只需提供一个一致的入口和数据契约。

## 页面、模块与数据流

1. 新增 `web/ordinary.html`、`web/ordinary.css`、`web/ordinary.mjs`，及小型纯函数模块 `web/ordinary-data.mjs`。`ordinary-data.mjs` 负责校验与转换 API 响应，页面模块只管请求、选择城市、显示状态与渲染。独立页面用纯 HTML/CSS/JS，不新增前端框架。
2. 默认城市设为广州（经纬度固定且界面明确显示“广州”）；用户输入地名后调用 [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api)，显示至多五个候选城市及所属行政区供选择，不自动采用第一个重名结果。仅持久化用户选择的城市名、经纬度及必要的地区标识；浏览器无存储权限时仍能使用当前会话。无需位置权限。
3. 选定城市后调用 [Open-Meteo Weather Forecast API](https://open-meteo.com/en/docs)，请求 `current` 的温度、体感温度、相对湿度、天气代码和 10 m 风速；`hourly` 的温度、天气代码、逐小时降水及降水概率；`daily` 的天气代码、最高/最低气温、累计降水及最高降水概率。使用 `forecast_days=7`、`timezone=auto`，温度摄氏度、风速 km/h、降水 mm。默认最佳匹配模式；界面称“模式当前场 / 模式预报”，不称站点实况或官方预警。
4. 请求 `timeformat=unixtime`，逐小时记录以绝对时间判断有效期，并在 API 返回的 `timezone` 时区显示；从当前时刻起选择未来 24 个小时，不拿昨天时次凑数。每天的日期按 API 提供的时区显示；校验 `current`、`hourly`、`daily` 所需数组及长度，缺项单独显示“暂无数据”。天气代码仅映射到已定义的 WMO 类别，未知代码显示“未分类天气”。数值 `null` 不转成零，不对缺测降水求和。
5. 首次加载、地名无结果、请求失败、部分字段缺测分别有可见状态。城市搜索与预报请求并发时只显示最新一次选择的结果，提供“重试”按钮。使用 `textContent` 渲染 API 中的城市和描述文本。页面展示数据来源、更新时间、城市时区及“模式预报仅供参考”。没有成功数据时不保留上一个城市的天气卡片。
6. Web 的 `ordinary.html` 与现有 `index.html` 相互提供本地导航；专业图集的产品按钮、地图、会商计算不因普通天气页而改写。

## Android 与 Windows 入口

- Android 两个按钮加载打包于同一 APK 的普通天气页与专业图集页。使用 AndroidX WebViewAssetLoader 的 HTTPS 虚拟来源访问 assets，取消 `file:///` 所需的 `setAllowUniversalAccessFromFileURLs(true)`；保留必要的 `INTERNET` 权限。阻止不受控的 WebView 导航直接替换应用页面，站外链接交给系统浏览器。移除已经失效的旧 Site `launch_url`、`asset_statements` 配置，更新相关测试和说明。
- Windows 继续使用现有 `app.atmosscope.local` 虚拟主机映射；普通天气改到该主机的 `/ordinary.html`，专业图集保留 `/index.html`。`IsTrusted` 仅允许本地虚拟主机留在应用内，外部站点交给系统浏览器。更新顶部说明。
- 两端仍需外部气象 API 的可用网络；本阶段不替换专业图集 Leaflet / Plotly CDN，也不将离线预报写入安装包。

## 部署与数据使用边界

页面作为静态文件可以由普通 HTTPS 站点提供，但本阶段只交付仓库内可本地运行、可打包的页面和打包入口；域名、服务器、TLS、国内访问路径和运营资质须在单独的部署决策中确定。无需为了站点独立而改变现有 v1.6.0 发布标签或覆盖已发布安装包。

[Open-Meteo 当前使用条款](https://open-meteo.com/en/terms)对免费 API 规定非商业用途和调用限制。新页面默认只在用户打开、切换城市或主动重试时发请求，不后台高频轮询；准备公众部署时先核对实际用途、预计流量和许可方案，再决定免费端点是否适用。页面提供来源署名。

## 验收与发布边界

- 纯函数测试覆盖无结果城市、重名候选、空字段、不等长数组、时间窗口跨日、时区显示、零降水与缺测、未知天气代码。
- Chrome 在受控 API 响应下验收三组天气内容、城市切换、刷新、错误降级、移动屏布局与正确导航；再做一次真实 API 请求检查字段，但真实 API 数据不写入易变的断言。
- CI 在无签名密钥的 PR 中运行 Node 测试、JS 语法、浏览器烟测、Android debug 编译与 Windows 编译；正式签名与新版本发布在 PR 验收后进行。页面与两个安装程序均不得再引用 `chatgpt.site`；已发布的 v1.6.0 文件保持原样。
- 完成代码不等于已经获得公开网址。只有在实际部署并从未登录环境成功访问后，才宣布公开网站可用。

## 明确延期

旧 Site 的逐屏复刻、设备自动定位、收藏多城市、天气预警、穿衣建议、公网部署、离线天气数据、更高分辨率模式以及专业图集的 CDN 本地化，均不属于这轮普通天气入口交付。若取得旧站点源码，可在后续迭代做逐项迁移对照。
