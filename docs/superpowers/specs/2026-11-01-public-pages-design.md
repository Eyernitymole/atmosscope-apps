# AtmosScope 非商业公开体验版部署设计

日期：2026-11-01  
基线：`main` 的 v1.7.1 提交 `06de07f12d893156fbc5375b7d9db774b90039a1`  
阶段：静态网站公开部署；不改变 Android、Windows 安装包

## 意图、范围与边界

用户希望在无需安装应用或登录 ChatGPT 的情况下，通过公开网址访问已有普通天气和专业图集。第一阶段是无广告、无订阅的非商业体验版，沿用仓库 `web/` 页面及其现有数据来源。普通天气需要外网获取 Open-Meteo 的地理编码和预报；专业图集还依赖其原有的数据源、Leaflet/Plotly CDN。公开托管不代表离线可用，也不保证中国大陆网络稳定或官方预警能力。

目标：公开普通天气直达地址、专业图集地址；导航互通；可重复部署；从未登录环境验收。非目标：自定义域名、国内服务器或备案、商业服务、付费 API、改造气象算法、发布新安装包。不能以工作流成功代替实际公网访问验收；不能把模型当前场称为站点实况。

Open-Meteo 免费 API 仅用于非商业用途，适用其署名/许可与调用限制（当前条款为每日少于 10,000 次、每小时 5,000 次、每分钟 600 次）。若加入广告、订阅、商业推广或实际调用量超过限制，先停止按本设计公开运营，重新确定商业许可和服务架构。公开前核对页面对 Open-Meteo、RainViewer、OSM 等来源的标注和使用边界。

## 方案比较与选择

- GitHub Pages + Actions：发布仓库已有 `web/` 静态目录，单一源码、变更小；需要仓库拥有者在 Settings → Pages 选择 GitHub Actions，且不能承诺中国大陆可达。选择此方案。
- 独立站点托管：可能提供另一套地址与部署控制，但要维护第二套项目与权限，不符合本阶段最小变更。
- 国内托管及商业数据授权：适合日后稳定访问/商业运营，但涉及域名、备案、成本与数据许可，超出已确认的非商业体验范围。

## 页面与部署契约

`web/index.html` 继续是专业图集，`web/ordinary.html` 是普通天气；公开地址分别预期为 `https://eyernitymole.github.io/atmosscope-apps/index.html` 和 `https://eyernitymole.github.io/atmosscope-apps/ordinary.html`。两页现有相对链接和相对资产路径保持不变，不把专业图集覆盖成普通天气。默认根地址仍会落到专业图集，向用户给出的普通天气链接必须带 `/ordinary.html`。

新增独立 Pages 工作流：只在 `main` 的 `web/**` 或工作流自身变更时部署；签出代码，将 `web/` 作为静态产物上传并使用官方 Pages 部署动作；授予最小的 `contents: read`、`pages: write`、`id-token: write` 权限，使用 `github-pages` 环境和并发保护。不把仓库根目录、Android/Windows 构建产物、密钥或诊断日志发布到网页。保留现有 CI/Release 工作流的职责。

README 更新公开网址、非商业及联网限制、Pages 设置步骤、部署状态与排障入口；Pages 尚未启用时不得宣称已上线。部署的自动检查验证产物中的两个入口及关键相对资源；现有 `npm test` 和浏览器烟测继续覆盖页面功能。合并后检查 Pages 工作流成功，再从未登录浏览器分别打开两个实际地址，确认资源加载、页面互链、城市搜索和天气请求状态；外部数据源不可达时明示失败，不伪造预报。

## 外部依赖与交付门槛

仓库当前 `has_pages: false`。当前 GitHub 连接不提供仓库 Pages 管理接口，不能代替拥有者启用设置。用户在仓库 Settings → Pages 将 Source 设为 GitHub Actions 后，部署工作流才可形成公开站点；若设置未开启或部署失败，报告为“代码待部署/待验收”，不交付一个未经验证的可用网址。公开前还需检查 API 实际可用性与流量；商业化和中国大陆稳定访问另立项目。
